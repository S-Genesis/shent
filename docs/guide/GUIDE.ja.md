# SHENT：コミュニティのためのピアツーピア電子現金システム

## 概要

純粋なピアツーピア型の電子現金があれば、いかなる機関も経由せずに、ある人から別の人へ支払いを送ることができる。デジタル署名は問題の一部を解決するが、同じコインが二重に使われるのを防ぐために信頼できる第三者が依然として必要であれば、主な利点は失われる。SHENT は二重支払いの問題をピアツーピアネットワークによって解決する。ネットワークは取引をブロックチェーンに記録し、各ブロックはプルーフ・オブ・ワークによって封印される。こうしてできた記録は、その作業をやり直さない限り変更できない。最長のチェーンは、ブロック数ではなく累積作業量で測られ、出来事の順序の証明であると同時に、それが最大の計算能力から生まれたことの証明となる。その計算能力の大部分が、ネットワークを攻撃するために協力しないノードの手にある限り、それらのノードが最長のチェーンを生成し、いかなる攻撃者をも上回る。ネットワーク自体に必要な構造は最小限である。メッセージはベストエフォートで配信され、ノードはいつでも離脱し、また戻ることができる。その際、最も多くの作業が積まれたチェーンを、不在の間に起きたことの証明として受け入れる。

SHENT はコミュニティ通貨である。ジェネシスブロックは、その本文自体でそれを述べている：`SHENT 13/10/2026 - moneda comunitaria sin valor monetario`（金銭的価値のないコミュニティ通貨）。いかなる市場でも取引されておらず、アプリケーションは何も売買せず、何らかの価値を持つようになると約束する者もいない。

## 1. はじめに

我々が日常的に使う電子マネーは、ほとんどの場合、支払いを処理する仲介者に依存している。この仕組みは機能しているが、信頼に基づくモデル特有の弱点を抱えている。取引は取り消すことができ、仲介コストは少額の支払いを制約し、各当事者は必要以上の情報を提供しなければならない。

必要なのは、信頼ではなく暗号学的証明に基づく支払いシステムであり、任意の二者が互いに直接取引できるようにするものである。計算上取り消しが不可能な取引は受取人を保護する。取引の順序を記録し、それを作業によって封印するネットワークは、二重支払いを防ぐ。

SHENT はこの考えの実装である。ウォレット、マイニング、P2P ネットワークを備えたフルノードであり、一般的なパーソナルコンピュータで動作する。

## 2. アカウントと取引

SHENT はアカウントモデルを採用する。各アカウントは**アドレス**で識別される。アドレスは Ed25519 公開鍵から得られる。すなわち、その SHA-256 の先頭 20 バイトを、ネットワークのプレフィックス（メインネットでは `shent1…`、テストネットでは `tshent1…`、ローカルネットワークでは `rshent1…`）を付けて Bech32m でエンコードしたものである。アカウントが最初の取引を送信するまで、アドレスから公開鍵は明らかにならない。

各アカウントは**残高**と **nonce**（送信済み取引のカウンター）を持つ。送金には次のものが含まれる：

- 送信者の公開鍵
- 送金先アドレス
- 金額と手数料
- アカウントの次の nonce
- 任意の有効期限の高さ
- 最大 80 バイトの任意のメモ
- 以上のすべてとネットワーク識別子に対する Ed25519 署名

nonce は、他の設計において過去の出力への参照が果たす役割を担う。あるアカウントの各取引は、一度だけ、かつ順番どおりにしか使えない。同じ nonce を持つ二つの取引は二重支払いの試みであり、ネットワークはそのうち最大一つしか受け入れない。署名にはネットワーク識別子が含まれるため、テストネットで有効な取引はメインネットでは使えない。

金額は整数として保存される。1 SHENT は 100,000,000（1 億）単位である。金額に浮動小数点数は使われない。

## 3. ブロックとチェーン

各ブロックはヘッダーと取引のリストを含む。ヘッダーには、前のブロックのハッシュ、取引の Merkle ルート、タイムスタンプ、難易度ターゲット、そしてプルーフ・オブ・ワークの nonce が含まれる。各ブロックが前のブロックのハッシュを含むため、ブロックはチェーンを形成する。あるブロックを変更するには、そのブロックとそれ以降のすべてのブロックの作業をやり直さなければならない。

ブロックは、次の条件を満たす場合にのみ有効である：

- タイムスタンプが直前 11 ブロックの中央値より大きく、かつ 5 分を超えて未来の時刻ではない。
- ブロックのサイズが 1,000,000 バイト以下である。
- 最初の取引がマイナーへの報酬（coinbase）であり、規定どおりの額を正確に支払う。
- その他のすべての取引が、有効な署名、順番どおりの nonce、十分な残高を備えている。

## 4. プルーフ・オブ・ワーク

ブロックを封印するには、ヘッダーのハッシュが難易度ターゲットを下回るような nonce を見つけなければならない。SHENT はプルーフ・オブ・ワークのハッシュ関数として **Argon2id** を使用し、1 回の試行あたり 2 MiB のメモリを用いる。これは「メモリハード」（memory-hard）な関数である。各試行には計算に加えてメモリが必要であり、そのため個人の CPU の性能が専用機器の性能に近づく。専用機器を不可能にするわけではない。その優位を縮めるだけである。

その nonce を見つける近道はない。各試行は独立しており、成功確率はどの試行でも同じである。一方、検証にはハッシュ 1 回分の計算しかかからない。

難易度はブロックごとに直近 60 ブロックを見て再計算され、マイナーが少なくても多くても、**平均して 10 分に 1 ブロック**が生成されることを目標とする。計算能力が加われば難易度は上がり、抜ければ下がる。

## 5. ネットワーク

ネットワークは次の手順で動作する：

1. 新しい取引はすべてのノードに配信される。
2. 各ノードは新しい取引を一つのブロックにまとめる。
3. マイニングを行う各ノードは、自分のブロックのプルーフ・オブ・ワークを探す。
4. あるノードがそれを見つけると、そのブロックを他のすべてのノードに配信する。
5. 他のノードは、そのブロックのすべての取引が有効で、かつ以前に使われていない場合にのみ、ブロックを受け入れる。
6. ノードは、受け入れたブロックのハッシュを前のブロックとして使い、次のブロックの作業に取りかかることで、受け入れを表明する。

ノードは他のいかなるノードも信頼しない。各ブロックと各取引は、既知のノードから届いたものであっても、コンセンサスルールに従ってローカルで検証される。ネットワークのメッセージはそれ自体でコインを入金することはできない。残高を変えるのは、最も多くの作業が積まれたチェーンに含まれる有効なブロックだけである。

ノードは互いを見つけるために中央サーバーに依存しない。三つの経路を同時に使う：

- BitTorrent の公開 DHT。各ノードは、ネットワークとそのジェネシスブロックから導かれるキーの下に自分のポートを公開する。
- ローカルネットワーク内での検出。
- ピア間でのアドレス交換。

見つかった各アドレスはハンドシェイク（handshake）を経る。そこでは双方が、自らの Ed25519 アイデンティティでランダムなチャレンジに署名する。ネットワークが機能するには、少なくとも一つのノードが着信接続を受け付けていれば（メインネットでは TCP ポート 37373 を開放）十分である。ポートを開放していないノードは、リレー（relay）を経由して接続を受けることができる。

## 6. インセンティブ

慣例により、各ブロックの最初の取引は、そのブロックをマイニングした者に帰属する新しいコインを生成する。これはネットワークを支えるインセンティブであり、発行する機関なしにコインが流通に入る唯一の方法である。

- 報酬は**1 ブロックあたり 50 SHENT** である。
- **1,000,000 ブロック**（100 万）ごとに半減する（10 分間隔のブロックで約 19 年）。
- 総量が **100,000,000 SHENT**（1 億）を超えることはない。
- さらに、マイナーは自分が含めた取引の手数料を受け取る。

報酬はブロックを見つけた者のものであり、分配されない。マイナーが多数いる場合、各マイナーは全計算能力に占める自分の割合に比例した頻度でブロックを見つける。平均すれば分配と同じ結果になるが、それは丸ごとの、ランダムな報酬という形をとる。

インセンティブは、ノードが誠実であり続ける助けにもなる。他の全員を合わせたよりも多くの計算能力を集めた者は、それを使って履歴を書き換えるか、ルールに従って新しいコインを得るかを選ばなければならない。自らの富が依存するシステムを損なうよりも、ルールの範囲内で行動するほうが、その者にとって得である。

## 7. 競合するチェーン

二つのノードがほぼ同時にブロックを見つけることや、ノードの一群が切断されたまま独自にマイニングしていたことが起こりうる。その場合、チェーンには二つのバージョンが存在する。ノードは最初に受け取ったほうの上で作業を続けるが、もう一方がそれを追い越す場合に備えて保持しておく。この拮抗は次のブロックが現れたときに解消される。**累積作業量がより多い**分岐が、すべてのノードで有効なものとなる。

チェーンは統合されない。敗れた分岐のブロックは破棄され、それとともにその報酬も失われる。それらに含まれていた取引は、まだ有効であれば再び保留状態に戻る。ルールに従ってマイニングされたブロックは、最も多くの作業が積まれたチェーンに残っている限り、その報酬を保持する。したがって、高額の支払いを確定とみなす前にいくつかの承認を待つのが望ましく、またネットワークに接続した状態でマイニングするのが望ましい。孤立したノードは有効なブロックをマイニングしても、後にそれが他のノードのチェーンに敗れることがある。

保護のための規則が二つある：

- **最大再編成深度**：ノードは、すでに受け入れたブロックを 288 個（約 2 日分）を超えて置き換えることはない。
- **チェックポイント**：公開されたプログラムには、すでに履歴の奥深くに埋もれたいくつかのブロックのハッシュが含まれている。

どちらも長期にわたる攻撃の被害を制限するが、その代わりに、ダウンロードするソフトウェアへのわずかな信頼を必要とする。これは意図的な、周知の設計上の判断である。

## 8. プライバシー

従来の銀行モデルは、情報へのアクセスを制限することでプライバシーを実現する。SHENT では、あらゆる公開台帳と同様に、すべての取引が見える。アドレス、金額、時刻である。プライバシーは別の方法で保たれる。アドレスには名前がない。

備えている対策：

- **受け取りごとの新しいアドレス**。ウォレットは「受取」が求められるたびに新しいアドレスを生成する。すべて同じバックアップから導かれるが、外から見ると互いに関係がない……一つの支払いで一緒に使われるまでは。
- **Dandelion++**。自分の取引は、まずノードのランダムな経路を通り、その後に初めて配信される。どの IP から送られたかが明らかにならないようにするためである。
- **Tor**。ノードは SOCKS5 プロキシ経由でのみ接続することができる。このモードでは接続を待ち受けず、DHT、ローカルネットワーク、UPnP も使用しない。

暗号化について、誤解のないように述べておく：

- **秘密鍵は暗号化される**。ただし、それは各人のコンピュータ上においてのみである。
- **ブロックチェーンは暗号化されない**。これは意図的である。各ノードは、すべての取引を読み、検証できなければならない。ブロック、送金、残高は、ノード間でほぼリアルタイムに平文で共有される。それらを偽造できないのは、署名され作業によって封印されているからであって、隠されているからではない。
- **P2P プロトコルも暗号化されない**。ビットコインのプロトコルと同様である。接続を観察する者は、そのコンピュータが SHENT を実行していること、そしてどの公開データが流れているかを見ることができる。IP を隠すには Tor モードがある。

## 9. ウォレットとバックアップ

鍵は、オペレーティングシステムの乱数生成器を用いて、そのコンピュータ自身の上で生成される。鍵は `.shent` ファイルに保存され、このファイルはマスターパスワードで暗号化される（Argon2id + ChaCha20-Poly1305）。秘密鍵がそのコンピュータの外に出ることはなく、ネットワークを通じて送信されることもない。

- ファイルとパスワードがなければ、コインは回復できない。回復の仕組みは存在しない。誰もパスワードをリセットできない。
- `.shent` ファイルのコピーをコンピュータの外（USB メモリ、クラウド）に保管し、パスワードを安全な場所に保管しなければならない。
- ファイル、パスワード、鍵を誰とも共有してはならない。開発者もノードも、それらを要求することは決してない。

## 10. セキュリティと限界

ネットワークの残りよりも多くの計算能力を持つ攻撃者は、次のことができる：

- 最近のブロックを書き換える
- 自分自身の取引を取り消す（二重支払い）
- 他者の取引が承認されるのを妨げる

一方、次のことはできない：

- 無からコインを生み出す
- 鍵を持っていないアカウントのコインを使う
- ルールを変更する

誠実なノードは、どこから来たものであれ、無効なブロックをすべて拒否する。

セキュリティは、誠実な計算能力がどれだけあるかに依存する。マイナーの少ない若いネットワークでは、強力なコンピュータ 1 台が過半数を占めることもありうる。アプリケーションの「統計」ページは、直近数日間にいくつのアドレスがマイニングしたかを表示し、一つのアドレスがブロックの半数を超えて占めている場合に警告する。

このソフトウェアは現状のまま、いかなる保証もなく提供される。いかなるシステムも無敵ではない。ルール、コード、テストは公開されており、誰でも確認できる。

## 11. 実際の使い方

### インストール（Windows 10/11、64 ビット）

1. リポジトリの *Releases* ページから `SHENT-<version>-win-x64.zip` をダウンロードする。
2. `Get-FileHash .\SHENT-<version>-win-x64.zip -Algorithm SHA256` でハッシュを検証し、公開されている `.sha256` ファイルと比較する。
3. zip を丸ごと展開し、`SHENT.exe` を開く。他に何かをインストールする必要はない。
4. Windows ファイアウォールが確認を求めてきた場合は、他のノードが接続できるようにアクセスを許可する。

### 最初の手順

- **ウォレット → ウォレットを作成**。マスターパスワードを決め、`.shent` バックアップを保存する。
- **マイニング**。スレッド数と強度を選び、リアクターを起動する。接続中のピアがない場合、アプリケーションはその旨を警告する。ネットワークなしでマイニングしたものは破棄される可能性がある。
- **送金**。送金先アドレス、金額、手数料を貼り付ける。署名の前に確認画面を見直す。
- **受取**。表示されたアドレスを共有する。アドレスは公開されているものであり、それによって何かを使うことはできない。
- **言語**。地球儀のセレクターで、インターフェースを 10 言語の間で切り替えられる。金額は選択した言語の小数点記号で入力する。金額があいまいな場合、アプリケーションは推測せずにそれを拒否する。

### ネットワークを強くする

ルーターで **TCP 37373** ポートをこのコンピュータに向けて開放するか、UPnP を有効にする。接続を受け付けるノードが一つ増えるごとに、他の人が参加しやすくなる。画面のないサーバー向けには、コンソールノードがある：`nodo-consola\shent-node.exe help`。

### ソースコードからビルドする

.NET 10 SDK が必要である。

```
dotnet build Shent.sln
dotnet test tests/Shent.Core.Tests
dotnet run --project src/Shent.Desktop
```

Windows 向けリリースは `scripts/publish-windows.ps1` で生成される。ネットワークの技術文書は [`docs/P2P_INTERNET.md`](../P2P_INTERNET.md) にある。

## 12. 結論

我々は、信頼に依存しない電子取引のシステムを提案した。デジタル署名は、鍵を持つ者にコインの管理権を与える。二重支払いを防ぐため、ネットワークは取引の公開履歴をプルーフ・オブ・ワークのチェーンに記録する。誠実なノードが計算能力の大部分を握っている限り、攻撃者がこのチェーンを改ざんすることは不可能になる。ネットワークはその単純さゆえに堅牢である。ノードはごくわずかな調整で同時に作業し、身元を明かす必要がなく、いつでも離脱し、また戻ることができる。その際、最も多くの作業が積まれたチェーンを、起きたことの証明として受け入れる。ノードは計算能力によって投票する。有効なブロックの上で作業することでそれを受け入れ、無効なブロックの上での作業を拒むことでそれを退ける。必要なルールとインセンティブはすべて、この唯一のコンセンサスの仕組みによって課される。

SHENT は、コミュニティが使い、学び、改良するために存在する。
